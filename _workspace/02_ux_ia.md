- 대상: https://www.aikorea.go.kr (대통령직속 국가인공지능전략위원회, NAIS)
- 분석가: ux-ia (site-analysis-team)
- 분석 일시: 2026-06-05 (KST)
- 입력: `_workspace/01_inventory/`(INVENTORY.md, sitemap.md, pages/, screenshots/) + **라이브 사이트 브라우저 실측 검증**(Chrome MCP, DOM 조사·과업 흐름 추적·실제 검색 수행·메뉴 인터랙션 캡처)
- 평가 프레임: 닐슨 10대 사용성 휴리스틱

## 요약 (3~5줄)

메인의 풀스크린 히어로, 데스크톱 메가메뉴(한 번 호버에 전 하위메뉴 노출), 게시판 표 구조, 모바일 반응형은 전반적으로 양호하다. 그러나 **현재 위치를 알려주는 단서가 전무**하다 — breadcrumb·로컬내비(LNB)·페이지별 `<title>`·본문 헤딩이 모두 없어 사용자가 "내가 사이트 어디에 있는지"를 인지할 수 없다. **섹션 내 형제 페이지 이동 수단(LNB)이 없어** 게시판을 옮길 때마다 GNB를 다시 펼쳐야 하고, **상위 메뉴는 `javascript:;` 더미 링크**라 클릭해도 목적지가 없다. 통합검색이 콘텐츠/게시물로 이원화돼 핵심 정책어 검색 시 첫 영역이 "0건"을 보여주는 혼란이 있다. 핵심 과업(정보 열람) 자체는 수행 가능하나, **위치 인지·맥락 유지·탐색 효율** 차원에서 개선 여지가 크다.

**깊이 측정 (목표 도달 클릭 수, 데스크톱 기준):**
- 콘텐츠/게시판 목록 도달: **2클릭**(상위 호버 → 하위 클릭). 메가메뉴라 호버 한 번에 전 항목 노출 → 양호.
- 게시글 본문 도달: **3클릭**(상위 → 목록 → 행 클릭). 정부 게시판 표준 수준.
- 위원 소개의 분과위원/특별위원 등 탭 콘텐츠: 2클릭 + 페이지 내 탭 1 = 실질 3단계(탭이 별도 URL 없이 동작 정황).

**구조적 문제 요약:**
1. **현재 위치 표시(breadcrumb) 전무** — 모든 내부 페이지에서 `.location/.breadcrumb` 요소 0개(실측: content.do·brdList.do 공통 `hasLocation:false`).
2. **로컬 내비게이션(LNB) 전무** — 섹션에 들어가도 좌측/지역 메뉴가 없어(`hasLNB:false`) 형제 페이지로 직접 이동 불가. 게시판→다른 게시판 이동에 GNB 재펼침 필수.
3. **상위 카테고리가 빈 링크** — "위원회 개요/활동/소통공간"이 `href="javascript:;"`(실측). 카테고리 랜딩/개요 페이지 없음.
4. **메뉴 체계 이중성** — GNB는 3카테고리, 전체메뉴 오버레이는 4번째 "이용안내"(통합검색·사이트맵)를 추가로 노출. 사용자가 통합검색의 위치를 일관되게 인지하기 어려움.
5. **페이지 식별 정보 부재** — 모든 페이지 `<title>`이 "국가인공지능전략위원회"로 동일(실측). 본문에 페이지 제목 헤딩도 없음(`#container` 내 h1~h6 = 0개).

## 강점

- **데스크톱 메가메뉴(인식 우선, 닐슨 #6)** — 상위 메뉴 1회 호버로 3개 컬럼 전 하위메뉴를 동시 노출(실측 캡처). 사용자가 기억하지 않고 한눈에 전체 구조를 인식. 정부 사이트 중 우수한 패턴.
- **스킵 네비게이션 제공(닐슨 #7)** — "본문 바로가기/주메뉴 바로가기" 2종(`pages/01_main.md`). 키보드·스크린리더 효율 보조.
- **전체메뉴(사이트맵) 오버레이** — 햄버거(☰) 클릭 시 4개 카테고리 전체를 한 화면에 펼침(실측). 전역 탐색 보조 수단으로 유효.
- **모바일 반응형 정상 동작(닐슨 #4)** — `screenshots/main_mobile.png`, `about_mobile.png`에서 단일 컬럼 재배치·가로 스크롤 없음 확인. 히어로/카드/푸터가 깨짐 없이 적층.
- **게시판 표의 구조적 일관성** — 11종 게시판이 번호/제목/작성자/첨부/등록일/조회 동일 컬럼 체계(`pages/06_boards.md`). 갤러리형(카드뉴스/사진/동영상)은 카드 그리드로 콘텐츠 성격에 맞게 분기 — 표준·일관성 양호.
- **검색 결과의 출처 경로 표기** — 검색 결과 항목마다 "소통공간 > 카드뉴스" 식 카테고리 경로 표시(실측 캡처). 역설적이지만 검색결과에는 위치 단서가 있음(본문 페이지엔 없음).
- **빠른 초기 응답** — 메인 HTML TTFB 0.15~0.24s(인벤토리 tech). 체감 로딩 가벼움.

## 발견 사항

### [치명] 현재 위치를 알 수 없음 — breadcrumb·LNB·페이지 식별 정보 전면 부재 (닐슨 #1 시스템 상태 가시성)
- 근거: 라이브 실측 — content.do?menu_cd=000005·brdList.do?menu_cd=000011에서 `hasLocation:false`, `hasLNB:false`, `#container` 내 헤딩 0개, 모든 페이지 `<title>="국가인공지능전략위원회"` 동일. 페이지 제목 텍스트('위원회 소개'·'정책자료')는 `<a>` 태그로만 존재.
- 영향: 깊은 페이지로 외부 링크/검색으로 진입한 사용자(다수)가 "여기가 어느 메뉴인지", "상위로 어떻게 가는지"를 알 수 없다. 브라우저 탭·북마크가 전부 같은 이름이라 여러 페이지를 열어두면 구분 불가. 정부 정보 사이트에서 위치 인지 실패는 신뢰·효율을 직접 훼손.
- 권고: (1) 본문 상단에 breadcrumb 추가("홈 > 소통공간 > 정책자료"), (2) 각 페이지에 고유 `<title>`("정책자료 | 국가인공지능전략위원회"), (3) 페이지 제목을 `<h1>`/`<h2>` 헤딩으로 마크업. 검색결과에 이미 쓰는 카테고리 경로 로직을 본문 페이지에 재사용하면 저비용 구현 가능.

### [주요] 섹션 내 형제 페이지 이동 수단(LNB) 부재 — 매 이동마다 GNB 재펼침 (닐슨 #7 효율성)
- 근거: 라이브 실측 — 게시판/콘텐츠 내부 페이지에 좌측·지역 내비 0개(`hasLNB:false`). 정책자료에서 보도자료로 가려면 본문에 직접 링크가 없어 상단 GNB를 다시 호버/펼쳐야 함.
- 영향: "소통공간 내 여러 자료를 연속 열람"하는 전형적 과업에서 매번 상단으로 올라가 메뉴를 펼치는 반복 비용 발생. 모바일에선 매번 햄버거→전체메뉴 왕복이 더 부담.
- 권고: 콘텐츠/게시판 페이지에 현재 섹션의 형제 메뉴를 보여주는 LNB(또는 상단 탭 바)를 추가. 최소한 같은 카테고리 내 게시판 간 가로 탭이라도 제공.

### [주요] 상위 카테고리가 클릭 불가능한 더미 링크(`javascript:;`) — 카테고리 랜딩 없음 (닐슨 #3 사용자 제어/#2 실세계 일치)
- 근거: 라이브 실측 — "위원회 개요/활동/소통공간" 상위 `<a href="javascript:;">`. 클릭해도 이동 없음, 드롭다운 트리거 전용.
- 영향: 사용자는 "위원회 활동"을 클릭하면 활동 개요 페이지가 뜰 것으로 기대(실세계 일치 위반)하나 아무 반응 없음. 터치 기기에선 더 혼란(호버 부재로 1탭=펼침, 목적지 기대 깨짐). 키보드 포커스 시에도 목적지 없음(→accessibility 공유 완료).
- 권고: 상위 카테고리에 해당 섹션 개요/소속 메뉴 목록을 보여주는 랜딩 페이지를 연결하거나, 최소한 첫 하위 메뉴로 이동시켜 "클릭하면 뭔가 일어난다"는 기대를 충족.

### [주요] 통합검색의 콘텐츠/게시물 이원화 — 핵심어 검색 시 첫 영역이 "0건" (닐슨 #2 실세계 일치/#1 가시성)
- 근거: 라이브 실측 — '행동계획' 검색 결과 "콘텐츠 검색 총 0건 / 검색결과가 없습니다" 블록이 상단에 먼저 표시되고, 그 아래 "게시물 검색 총 147건"이 노출(실측 캡처). 기본 탭 '전체'는 두 결과를 세로로 적층.
- 영향: 사용자는 '행동계획'이 분명히 있는데 첫 화면에서 "검색결과가 없습니다"를 보고 사이트에 정보가 없다고 오인할 수 있다. 콘텐츠/게시물 구분은 사용자의 멘탈모델이 아닌 시스템(content.do vs board) 내부 구조를 노출한 것. content.do 본문이 빈약해 콘텐츠 검색이 사실상 무력화된 정황(→tech-seo-security 공유 완료).
- 권고: 기본 결과를 단일 통합 목록으로 합치고 관련도순 정렬, "콘텐츠/게시물" 구분은 필터 칩으로 강등. 0건 영역은 결과가 있을 때만 노출하거나 접어두기.

### [주요] 검색 입력의 동작 단서 부족 + form 시맨틱 미사용 (닐슨 #6 인식/#5 오류예방)
- 근거: 라이브 실측 — 검색 페이지에 `<form>` 0개, 입력 4개 중 일부 label 미연결(`pages/08_search.md`). Enter 키만으로는 검색이 트리거되지 않는 경우 관찰(JS 이벤트 의존), 가시 입력 옆 "검색" 버튼 클릭으로 동작.
- 영향: 키보드로 검색어 입력 후 Enter를 눌렀을 때 반응이 없으면 사용자는 무엇을 잘못했는지 모름(오류 예방·피드백 부족). 폼 시맨틱 부재로 보조기기 동작도 불안정(→accessibility 영역).
- 권고: 검색을 `<form>`으로 감싸고 submit(Enter) 동작 보장, 입력에 명시적 label/aria-label 연결, 검색 버튼에 가시 포커스 스타일.

### [주요] 게시판 목록 행이 `javascript:goToDetail(id)` — 실제 링크가 아님 (닐슨 #3 사용자 제어)
- 근거: 라이브 실측 — brdList tbody tr의 진입이 `javascript:goToDetail(586)`(href 없는 JS 이동). `pages/06_boards.md`와 일치.
- 영향: 새 탭으로 열기(Cmd/Ctrl+클릭)·우클릭 메뉴·링크 복사·중간 클릭이 모두 불가. 자료를 여러 개 새 탭으로 비교하려는 사용자(공무원·연구자 다수)의 효율 저하. 키보드/스크린리더 접근에도 불리(→accessibility 공유 완료).
- 권고: 목록 항목을 실제 `<a href="brdDetail.do?...">`로 마크업하고 JS는 보조로만. 새 탭/링크 공유 가능하게.

### [경미] 라벨 표기 비일관 — "컨텐츠" vs "콘텐츠", "메뉴얼" vs "매뉴얼" (닐슨 #4 일관성/표준)
- 근거: 라이브 실측 — 검색 탭 라벨은 "컨텐츠 검색", 본문/결과 헤더는 "콘텐츠 검색"으로 혼용. MI 소개의 "MI 사용 메뉴얼"(`pages/05_mi-intro.md`, 표준 표기 '매뉴얼').
- 영향: 정부 사이트의 표기 신뢰도에 미세한 흠. 검색 시 동일 개념이 다른 표기로 보임.
- 권고: 외래어 표기법 기준으로 "콘텐츠"·"매뉴얼"로 통일.

### [경미] 풀스크린 히어로가 첫 화면을 거의 점유 — 정보 스크롤 유도 약함 (닐슨 #8 미니멀/#1 가시성)

- 영향: 첫 화면에서 "최신 활동/정책자료"로의 정보 향(scent)이 약함. 방문 목적이 정보 열람인 사용자가 스크롤 필요성을 인지 못 할 수 있음.

## 주요 과업 흐름 분석 (과업별 클릭 경로 + 막힘 지점)

### 과업 A — "AI 행동계획 원문(정책자료)을 찾아 본다" (데스크톱)
1. 메인 → GNB "소통공간" 호버(메가메뉴 전개) → "정책자료" 클릭 **[2클릭, 매끄러움]**
2. 정책자료 목록 → "대한민국 인공지능 행동계획(한글, 인쇄본)" 행 클릭(`goToDetail`) **[3클릭째]**
3. 상세 페이지 → 본문은 없고 PDF 첨부 "다운로드" **[막힘: 본문 미리보기 불가, PDF 받아야 내용 확인]**
- 막힘 지점: (a) 상세에서 현재 위치 단서 없음(어느 게시판인지 본문에 미표시), (b) 핵심 내용이 PDF에만 있어 화면에서 바로 못 읽음(콘텐츠 영역 이슈, content-policy와 연관), (c) 새 탭으로 비교 열람 불가(JS 이동).
- 판정: **수행 가능하나 맥락·내용 즉시성에서 마찰.**

### 과업 B — "행동계획 관련 자료를 검색으로 찾는다"
1. 헤더 돋보기/통합검색 진입 → '행동계획' 입력 → 검색 버튼 클릭 **[Enter만으로는 미동작 관찰 → 막힘 후보]**
2. 결과: 상단 "콘텐츠 검색 0건 / 검색결과가 없습니다" → 스크롤 → "게시물 검색 147건" 노출 **[막힘: 첫 화면 0건으로 오인 위험]**
3. 결과 항목에 "소통공간 > 카드뉴스" 경로 표시 → "자세히보기" 클릭으로 진입 **[양호]**
- 막힘 지점: Enter 미동작 가능성, 첫 영역 0건의 부정적 첫인상, 두 결과셋 적층으로 스캔 부담.
- 판정: **결과는 풍부하나 표현 방식이 오인·비효율 유발.**

### 과업 C — "위원회가 어떤 활동을 하는지 둘러본다" (탐색형)
1. 메인 → "위원회 활동" 클릭 시도 **[막힘: `javascript:;` 더미 — 클릭해도 페이지 없음]**
2. 어쩔 수 없이 호버로 하위(전체회의/운영위/분과위/CAIO) 중 하나 선택 → 목록 진입
3. 다른 활동 게시판으로 가려면 **다시 GNB 재펼침**(LNB 없음) **[막힘: 형제 이동 반복 비용]**
- 막힘 지점: 카테고리 랜딩 부재로 "활동 전반 개요"를 한 페이지에서 못 봄, 게시판 간 회유 비효율.
- 판정: **탐색형 사용자에게 마찰 큼 — 개요 랜딩 + LNB 필요.**

### 과업 D — "모바일에서 특정 메뉴로 이동한다"
1. 모바일 메인 → 햄버거(☰) 탭 → 전체메뉴 오버레이(4카테고리 전개) **[양호: 한 화면에 전체]**
2. 원하는 항목 탭 → 목록 진입 **[2탭, 매끄러움]**
3. 형제 메뉴 이동 시 다시 햄버거 왕복 **[LNB 부재 반복 비용, 데스크톱과 동일]**
- 판정: **반응형 자체는 양호. 구조적 LNB 부재 문제는 모바일에서 더 부각.**

- **내비게이션(양호):** 햄버거 → 전체메뉴 오버레이가 4카테고리 전체를 한 화면에 펼쳐 모바일 탐색 효율 좋음(실측 확인).
- **인터랙션 주의:** 데스크톱 메가메뉴는 호버 기반인데 모바일은 탭으로 대체(전체메뉴 오버레이로 우회) — 일관되나, 상위 더미 링크(`javascript:;`)는 터치에서 "한 번 탭=목적지" 기대를 깨므로 데스크톱보다 혼란 가능.
- **터치 타깃:** 모바일 스크린샷상 메뉴/버튼 간격은 적절해 보이나, 게시판 표의 행·페이지네이션 숫자·검색 입력의 터치 타깃 최소 44px 충족 여부는 **실기기 정밀 측정 필요(시각 추정 한계 명시).**
- **기술적 원인 메모:** 모바일 깨짐은 관찰되지 않았으나, 뷰포트 메타/브레이크포인트 정합성 등 기술 검증은 tech-seo-security 영역(별도 공유함). 분석 중 브라우저 창 리사이즈(390px)로는 CSS 브레이크포인트가 전환되지 않아(렌더 1148px 유지) **모바일 평가는 인벤토리 모바일 스크린샷을 1차 근거로 사용**했음을 명시.
