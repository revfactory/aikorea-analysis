# KWCAG 검사항목 체크리스트 (한국형 웹 콘텐츠 접근성 지침)

접근성 진단의 점검 기준. 4원칙 체계 아래 검사항목별로 **점검 방법**과 **판정 기준**을 제시한다.

> **버전 주의:** 아래는 KWCAG 2.1(KS X OT0003, 2015)의 24개 검사항목을 핵심 골격으로 하고, KWCAG 2.2(2022.12 개정)에서 추가·강화된 항목을 함께 표기했다. KWCAG 2.2는 WCAG 2.1과의 정합성을 높여 단일 포인터 입력·고정 참조 콘텐츠·접근 가능한 인증 등을 보강했다. **공식 최신 검사항목 수·문구는 한국지능정보사회진흥원(NIA) "웹 접근성 연구소" 또는 TTA 공시본으로 반드시 교차 확인하고, 본 체크리스트에 없는 2.2 신규 항목이 있으면 보완 점검한다.** 항목 번호는 점검 편의를 위한 일련번호이며 공식 번호와 다를 수 있다.

## 원칙 1. 인식의 용이성 (Perceivable)
모든 콘텐츠는 사용자가 인식할 수 있어야 한다.

**1. 적절한 대체 텍스트 제공** (지침: 대체 텍스트)
- 점검: 모든 의미 있는 이미지(`<img>`, 배경 이미지로 정보 전달, CSS 아이콘)에 적절한 `alt`가 있는가. 장식용 이미지는 `alt=""`인가.
- 판정: alt 존재 + 내용이 이미지의 의미·기능을 정확히 전달 → 적합. alt 누락, "image", 파일명, 부적절한 설명 → 부적합.
- 방법: 인벤토리 HTML의 `<img>` alt 속성 전수 확인. 의미적 적절성은 수동 판단.

**2. 자막·대본·수어 제공** (지침: 멀티미디어 대체수단)
- 점검: 동영상·오디오에 자막(또는 대본/수어)이 제공되는가.
- 판정: 멀티미디어 없으면 해당없음. 있는데 자막 없으면 부적합.

**3. 색에 무관한 콘텐츠 인식** (지침: 명료성)
- 점검: 색만으로 정보를 전달하지 않는가(예: "빨간 항목은 필수" → 색+텍스트/기호 병행).
- 방법: 스크린샷에서 색 의존 정보 확인.

**4. 명확한 지시사항 제공**
- 점검: "오른쪽 버튼", "파란 영역" 등 감각적 특성에만 의존한 지시가 없는가.

**5. 텍스트 콘텐츠의 명도 대비**
- 점검: 일반 텍스트 4.5:1 이상, 큰 텍스트(18pt/14pt bold) 3:1 이상.
- 방법: 실제 전경/배경 색상값으로 대비 계산 또는 스크린샷의 명백한 저대비 식별. 정밀 측정 불가 시 "확인필요".

**6. 자동 재생 금지**
- 점검: 페이지 진입 시 소리가 자동 재생되면 정지 수단이 있는가(3초 초과 시).

**7. 콘텐츠 간의 구분**
- 점검: 인접한 콘텐츠를 시각·구조적으로 구분 가능한가(테두리·여백·제목 등).

## 원칙 2. 운용의 용이성 (Operable)
사용자 인터페이스는 조작 가능해야 한다.

**8. 키보드 사용 보장**
- 점검: 마우스 없이 키보드만으로 모든 기능(링크·버튼·폼·메뉴)을 사용할 수 있는가.
- 방법: **브라우저로 Tab/Shift+Tab/Enter/방향키 직접 테스트.** 정적 점검 불가 → 반드시 수동.

**9. 초점 이동과 표시**
- 점검: 초점 이동 순서가 논리적(읽는 순서)이고, 현재 초점이 시각적으로 보이는가(focus indicator).
- 방법: 브라우저 Tab 이동으로 순서·가시성 확인. 키보드 함정(focus trap) 없는지 확인.

**10. 조작 가능 (컨트롤 크기)**
- 점검: 클릭/터치 대상이 충분히 큰가(권장 최소 크기), 인접 컨트롤 간 간격이 적절한가.

**11. 응답시간 조절**
- 점검: 시간제한이 있는 콘텐츠(세션 만료 등)에 연장·해제 수단이 있는가.

**12. 정지 기능 제공**
- 점검: 자동 변경·이동·갱신 콘텐츠(슬라이드·캐러셀·티커)에 정지 수단이 있는가.
- 방법: 메인 페이지 배너/슬라이드 확인.

**13. 깜빡임·번쩍임 사용 제한**
- 점검: 초당 3~50회 번쩍임(광과민성 발작 유발)이 없는가.

**14. 반복 영역 건너뛰기 (Skip Navigation)**
- 점검: 페이지 상단에 본문으로 바로 가는 건너뛰기 링크가 있는가.
- 방법: HTML 최상단 skip link 존재 + 키보드로 동작 확인. 정부 사이트 핵심 항목.

**15. 제목 제공**
- 점검: 페이지마다 고유하고 적절한 `<title>`, 프레임 `title`, 콘텐츠 블록 제목(헤딩)이 있는가.

**16. 적절한 링크 텍스트**
- 점검: "여기", "클릭", "more"처럼 맥락 없는 링크가 아니라 목적지를 알 수 있는 링크 텍스트인가.

## 원칙 3. 이해의 용이성 (Understandable)
콘텐츠와 조작 방법은 이해 가능해야 한다.

**17. 기본 언어 표시**
- 점검: `<html lang="ko">`로 페이지 기본 언어가 명시됐는가.
- 방법: HTML 루트 lang 속성 확인.

**18. 사용자 요구에 따른 실행**
- 점검: 초점·입력만으로 의도치 않은 맥락 변화(자동 새 창·자동 폼 제출)가 일어나지 않는가. 새 창은 사전 고지하는가.

**19. 콘텐츠의 선형 구조**
- 점검: CSS를 제거해도 콘텐츠가 논리적 순서로 읽히는가. 헤딩 위계(h1→h2→h3)가 건너뛰지 않는가.
- 방법: 인벤토리 HTML의 헤딩 구조 확인.

**20. 표의 구성**
- 점검: 데이터 표에 제목 셀(`<th>`), `scope`, caption/summary가 적절한가. 레이아웃 목적의 표 남용이 없는가.

**21. 레이블 제공**
- 점검: 모든 입력 폼 컨트롤에 `<label>`(또는 적절한 연결)이 있는가.
- 방법: 인벤토리 HTML의 form/input/label 확인. 검색창 포함.

**22. 오류 정정**
- 점검: 입력 오류를 텍스트로 알리고 수정 방법을 안내하는가.

## 원칙 4. 견고성 (Robust)
다양한 사용자 환경·보조기술과 호환되어야 한다.

**23. 마크업 오류 방지**
- 점검: 요소 여닫기, 중복 속성, 중복 id 등 마크업 문법 오류가 없는가.
- 방법: HTML 검증(W3C validator 관점). tech-seo-security-analyst와 공유.

**24. 웹 애플리케이션 접근성 (이름·역할·값)**
- 점검: 커스텀 컨트롤(자바스크립트 위젯·탭·아코디언·드롭다운)이 이름(name)·역할(role)·상태/값(value)을 보조기술에 제공하는가(WAI-ARIA 적절 사용).
- 방법: 동적 위젯을 브라우저로 확인. 정적 점검 한계 시 "확인필요".

## KWCAG 2.2 추가·강화 점검 포인트
KWCAG 2.2(2022.12)는 WCAG 2.1 정합화로 다음을 보강했다. 해당 콘텐츠가 있으면 추가 점검한다.
- **단일 포인터 입력 지원**: 복잡한 제스처(다중 터치·드래그)에 단일 포인터 대안 제공.
- **드래그 동작 대안**: 드래그로만 가능한 조작에 클릭/탭 대안 제공.
- **고정 참조 위치 콘텐츠**: 고정 헤더/푸터가 콘텐츠나 초점을 가리지 않는가.
- **접근 가능한 인증**: 로그인·본인확인이 인지기능 테스트(기억·계산)에만 의존하지 않는가.
- **중복 입력 정보 최소화**: 같은 과정에서 이전에 입력한 정보를 자동완성·선택으로 줄이는가.
- **콘텐츠 가림 방지**: 초점 받은 요소가 다른 콘텐츠에 가려지지 않는가.

> 위 목록은 대표 항목이며 공식 2.2 검사항목 전수가 아니다. NIA/TTA 공시본으로 누락 항목을 확인한다.

## 점검 도구·방법 요약
| 점검 유형 | 방법 |
|----------|------|
| alt·헤딩·lang·label·표 구조 | 인벤토리 HTML 정적 분석 |
| 키보드 접근·초점 순서·focus trap | 브라우저 수동 테스트 (Tab/Enter) |
| 명도 대비 | 색상값 대비 계산 또는 스크린샷 식별, 불가 시 확인필요 |
| 자동재생·슬라이드 정지·동적 위젯 | 브라우저 실제 동작 확인 |
| 마크업 문법 | HTML 검증 관점, tech 분석가와 공유 |
| alt·링크 텍스트 의미 적절성 | 수동 판단 (기계적 존재와 구분) |

**핵심 원칙:** 자동으로 알 수 있는 것(존재 여부)과 사람이 판단해야 하는 것(적절성·실제 사용성)을 구분하여 보고한다. 검증하지 못한 항목을 적합/부적합으로 단정하지 말고 "확인필요"로 남긴다.
