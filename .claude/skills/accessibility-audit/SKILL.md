# Accessibility Audit — 웹 접근성 진단 절차 (KWCAG 기준)

모든 사용자(시각·청각·지체·인지 장애 및 고령자 포함)가 동등하게 이용 가능한지 진단한다.

## 왜 이것이 필수인가
한국 정부 사이트(.go.kr)는 「장애인차별금지법」과 「국가정보화 기본법」에 따라 웹 접근성 준수가 **법적 의무**다. 부적합은 단순 품질 문제가 아니라 차별 소지가 되는 법적 위험이다. 따라서 aikorea.go.kr 분석에서 접근성은 "권고"가 아니라 "준수 의무" 기준으로 본다.

## 시작 전 필수
평가 시작 전 반드시 [references/kwcag-2.2-checklist.md](references/kwcag-2.2-checklist.md)를 Read한다. 모든 검사항목을 빠짐없이 점검하기 위한 체크리스트이며, 항목별 점검 방법과 판정 기준이 담겨 있다.

## 판정 체계
각 검사항목을 다음 중 하나로 판정한다:
- **적합** — 기준 충족 (근거 제시)
- **부적합** — 기준 위반 (근거 + 위반 내용 + 수정안)
- **해당없음** — 해당 콘텐츠 유형이 사이트에 없음
- **확인필요** — 자동/정적 점검으로 판단 불가, 수동 검증 요함

## 절차
1. `references/kwcag-2.2-checklist.md`를 Read하여 검사항목 전체를 확보한다.
2. `_workspace/01_inventory/`의 HTML(alt, 헤딩, 폼 레이블, lang, 표 구조)을 1차 근거로 정적 점검한다.
3. **정적 점검으로 불가능한 항목은 브라우저로 직접 검증한다**:
   - 키보드만으로 모든 기능 사용 가능한가 (Tab/Enter/방향키)
   - 초점(focus) 이동 순서가 논리적이고 시각적으로 보이는가
   - 명도 대비(텍스트 4.5:1) — 스크린샷/실제 색상값으로 확인
   - 동적 콘텐츠·팝업·자동재생 동작
4. **기계적 존재 ≠ 의미적 적절성**을 구분한다. alt가 "있는지"와 alt가 "그림을 적절히 설명하는지"는 다르다. 둘 다 보고하되 구분한다.
5. 검증 불가 항목은 단정하지 말고 "확인필요"로 분류한다. 추정을 사실로 보고하지 않는다.
6. 부적합 항목마다 장애인차별금지법 관점의 위험과 구체적 수정안(코드 예시 가능)을 제시한다.
7. 검사항목 기준 준수율(%)과 100점 점수를 산정한다.

## 출력 형식
`_workspace/02_accessibility.md`:
```
# 웹 접근성 진단 (KWCAG 기준)
## 요약 (준수 수준 + 법적 위험도 한 줄)
## 원칙별 검사 결과표
| 원칙 | 검사항목 | 판정 | 근거 |
## 발견 사항 (부적합 상세)
### [치명|주요|경미] {검사항목} 부적합
- 근거: {HTML/스크린샷/키보드 테스트 결과}
- 법적 위험: {장애인차별금지법 관점}
- 권고: {수정 방법, 코드 예시 가능}
## 수동 확인 필요 항목
## 준수율 (검사항목 기준 % + 점수)
```

심각도 기준:
- 치명: 핵심 기능을 특정 장애 사용자가 전혀 사용 불가(예: 키보드 접근 불가, 핵심 이미지 alt 전무)
- 주요: 다수 항목 부적합으로 이용 곤란(예: 명도 대비 광범위 미달, 폼 레이블 누락)
- 경미: 부분적·보강 수준

## 협업 신호
- 키보드 내비/포커스 → ux-ia-analyst와 공유.
- 마크업 문법 오류·ARIA 누락 → tech-seo-security-analyst에 공유.
- alt가 있으나 내용 부적절 → content-policy-analyst에 의미 검토 요청.

## 하지 않을 것
- 키보드/명도 등 미검증 항목을 단정 보고(반드시 "확인필요"로 분류).
- 자동 점검만으로 "완전 준수" 선언(접근성은 상당 부분 수동 판단 필요).
