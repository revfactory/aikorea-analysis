# Content & Policy Audit — 콘텐츠·정책 진단 절차

"이 사이트가 방문자에게 충분하고 정확하며 최신의, 이해하기 쉬운 정보를 주는가?"를 근거 기반으로 판단한다. 정보의 **내용·정확성·충실성**을 다루며, 정보의 배치·탐색은 UX 분석가에게 맡긴다(역할 경계).

## 왜 이렇게 하는가
정부 정책 사이트의 핵심 가치는 정보 그 자체다. 화면이 예뻐도 정보가 낡거나 빈약하면 사이트는 목적을 잃는다. 공공 사이트는 투명성·정확성·접근성이 일반 기업보다 높게 요구되므로, 더 엄격한 기준으로 본다.

## 평가 축 5가지
각 축을 `_workspace/01_inventory/`의 실제 텍스트로 검증한다.

| 축 | 핵심 질문 | 단서 |
|----|----------|------|
| **충실성** | 핵심 정보가 충분한가 | 소개·구성·활동·정책·연락처 등 기대 정보의 존재/깊이 |
| **최신성** | 콘텐츠가 살아 있는가 | 게시물 최신 일자, 활동 내역 갱신 빈도, 방치된 페이지 |
| **정확성·일관성** | 사실이 맞고 페이지 간 일치하는가 | 기관명·비전·수치·날짜의 페이지 간 충돌, 깨진 참조 |
| **전달력** | 일반 국민이 이해하는가 | 전문 용어 해설, 핵심 메시지 명료성, 문장 길이·구조 |
| **정보 공백** | 기대되지만 없는 정보 | 추진 일정, 자료실/발간물, FAQ, 문의·민원 경로, 영문 정보 |

## 절차
1. `_workspace/01_inventory/INVENTORY.md`와 `pages/`를 읽어 전체 콘텐츠를 파악한다.
2. 5개 축을 순서대로 점검하고, 각 발견에 **출처 URL + 인용**을 단다. 인용 없는 인상 비평은 버린다.
3. 부족하면 브라우저/WebFetch로 해당 페이지를 직접 재확인한다.
4. 발견을 심각도(치명/주요/경미)로 분류한다.
   - 치명: 사실 오류, 법정 의무 정보 누락, 심각하게 낡은 핵심 정보
   - 주요: 중요한 정보 공백, 일관성 결여, 전달력 저해
   - 경미: 사소한 표현·보강 권고
5. 100점 만점 점수를 근거와 함께 부여한다.

## 출력 형식
`_workspace/02_content_policy.md`:
```
# 콘텐츠·정책 분석
## 요약 (3~5줄)
## 강점
## 발견 사항
### [치명|주요|경미] {제목}
- 근거: {출처 URL + 인용}
- 영향: {방문자/기관에 미치는 영향}
- 권고: {구체적 개선안}
## 정보 공백 목록
## 점수 (100점, 근거 포함)
```

## 협업 신호
- 잘 쓰였으나 묻혀 못 찾는 콘텐츠 → ux-ia-analyst에 위치 확인.
- 가독성 문제가 곧 사용성 문제 → ux-ia-analyst에 공유.
- 대체텍스트/다국어 등 접근성 연관 → accessibility-analyst에 공유.

## 하지 않을 것
- 출처 없는 단정, 진위 불명 사실의 확정 보고("검증 필요" 플래그로 남겨 synthesizer가 확인).
- UX·접근성·기술 영역 침범(겹치면 공유로 처리, 중복 평가 금지).
