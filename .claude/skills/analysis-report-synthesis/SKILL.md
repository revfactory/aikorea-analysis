# Analysis Report Synthesis — 검증·종합 리포트 통합 절차

4개 영역(콘텐츠·정책 / UX·IA / 접근성 / 기술·SEO·보안) 보고서를 **검증하고 종합**한다. 단순 취합이 아니라, 근거 없는 주장을 거르고 교차 이슈를 통합하여 의사결정자가 신뢰하고 행동할 단일 리포트를 만든다.

## 왜 검증이 핵심인가
분석가는 실제보다 문제를 부풀리거나, 인벤토리에 없는 것을 추정으로 단정할 수 있다. 통합자가 분석가가 아니었다는 점이 강점이다 — **독립적으로 증거와 대조**할 수 있다. 검증 없는 종합은 환각을 그럴듯하게 포장할 뿐이다.

## 검증 절차 (먼저)
1. 입력을 모두 읽는다: `_workspace/01_inventory/`(증거), `_workspace/02_content_policy.md`, `_workspace/02_ux_ia.md`, `_workspace/02_accessibility.md`, `_workspace/02_tech_seo_security.md`.
2. 각 발견에 대해 "증거를 보여달라"는 태도로 인벤토리와 대조한다:
   - **채택** — 인벤토리에 근거가 확인됨
   - **강등** — 근거가 약하거나 심각도 과장 → 등급 낮춤
   - **기각** — 인벤토리와 모순되거나 근거 전무
   - **검증필요** — 인벤토리로 판단 불가(수동 확인 영역)
3. 검증 결과를 `_workspace/03_verification_log.md`에 추적 가능하게 기록한다(발견 → 출처 분석가 → 대조 결과 → 처리).
4. 보안 발견은 "관찰된 사실"과 "추정 위험"을 분리한다. 과장 금지.

## 종합 절차
1. **중복 통합**: 같은 문제가 여러 영역에서 다른 이름으로 지적된 경우 하나로 묶고 영역 태그를 병기한다(예: 헤딩 구조 = 접근성 + SEO).
2. **교차 영역 이슈 부각**: 여러 영역에 걸친 근본 원인(예: 노후 CMS → 성능·보안·접근성 동시 영향)을 별도 섹션으로 드러낸다.
3. **우선순위화**: (심각도 × 영향 범위 × 개선 난이도)로 정렬하여 즉시/단기/중장기 로드맵을 만든다.
4. **점수 통합**: 영역별 점수의 산정 근거를 부록에 명시하여 비교 가능성을 확보하고 종합 점수·등급을 낸다.
5. 상충 발견은 삭제하지 않고 양쪽 출처를 병기한다.

## 출력 형식 (최종 리포트)
기본 경로 `aikorea_종합진단리포트_{YYYYMMDD}.md`:
```
# {사이트명} 종합 진단 리포트
## 1. 경영진 요약 (1쪽: 종합 점수, 핵심 강점 3, 시급 개선 3, 한 줄 결론)
## 2. 종합 점수표 (영역별 + 종합 + 등급)
## 3. 우선순위 실행 로드맵 (즉시/단기/중장기 × 항목 + 영역 태그 + 난이도)
## 4. 영역별 상세 분석
### 4-1. 콘텐츠·정책   ### 4-2. UX·정보구조
### 4-3. 웹 접근성     ### 4-4. 기술·SEO·보안
## 5. 교차 영역 이슈 (근본 원인 + 영향 영역)
## 6. 검증·한계 노트 (강등/기각 발견, 수동 확인 필요, 수집 한계)
## 부록: 방법론·데이터 출처·수집 일자
```

## 독자를 고려한 글쓰기
- **경영진 요약**: 비전문가(위원회 관계자)가 5분 안에 핵심을 파악하도록. 점수·핵심 3강점·시급 3개선·결론.
- **상세 섹션**: 실무자가 바로 고칠 수 있도록 근거·위치·수정안 명시.
- 모든 권고는 "무엇을·왜·어떻게·우선순위"가 분명해야 한다. "개선 필요" 같은 추상 조언 금지.

## 에러 핸들링
- 보고서 일부 누락: 해당 영역을 "미수집(분석 미완)"으로 명시하고 진행. 누락을 숨기지 않는다.
- 발견이 인벤토리와 모순: 기각하지 말고 6번 섹션에 "검증필요 — 주장과 증거 불일치"로 기록.

## 하지 않을 것
- 검증 없는 단순 복사·붙여넣기 통합.
- 심각도·보안 위험 과장.
- 상충 데이터 임의 삭제(출처 병기로 보존).
