# UX / IA Audit — 사용자 경험·정보구조 진단 절차

방문자가 **원하는 정보에 얼마나 쉽고 빠르게 도달하는가**를 평가한다. 정보의 내용이 아니라 **구조·배치·탐색·조작**을 본다(콘텐츠 내용은 content-policy 분석가의 몫).

## 왜 휴리스틱 평가인가
닐슨의 10대 사용성 휴리스틱은 수십 년간 검증된 범용 프레임으로, 발견을 일관된 언어로 분류하고 우선순위를 매기게 해준다. 각 발견을 휴리스틱에 매핑하면 주관적 취향이 아니라 확립된 원칙에 근거한 진단이 된다.

## 닐슨 10대 휴리스틱
1. 시스템 상태의 가시성 2. 시스템과 실세계의 일치 3. 사용자 제어와 자유 4. 일관성과 표준 5. 오류 예방 6. 인지보다 인식(기억 부담 최소화) 7. 사용의 유연성·효율 8. 미니멀·심미적 디자인 9. 오류 인식·진단·복구 지원 10. 도움말·문서

## 평가 영역
| 영역 | 점검 내용 |
|------|----------|
| **정보구조(IA)** | 메뉴 분류의 논리성·일관성, 깊이(목표 도달 클릭 수), 레이블 명확성 |
| **내비게이션** | 전역/지역 내비, breadcrumb, 검색 기능, 내부 링크 연결성, 현재 위치 표시 |
| **과업 흐름** | 주요 과업(활동 찾기·자료 열람·문의)을 완수하는 경로의 매끄러움과 막힘 지점 |
| **반응형/모바일** | 데스크톱/모바일 레이아웃, 터치 타깃 크기, 가로 스크롤·잘림 |
| **인터랙션** | 링크/버튼 명료성, 로딩·오류 피드백, UI 패턴 일관성 |

## 절차
1. `_workspace/01_inventory/sitemap.md`로 메뉴 트리를 재구성하고 깊이를 측정한다.
2. `screenshots/`로 시각·모바일을 검토한다. 없으면 브라우저로 직접 캡처한다.
3. **과업 기반 검증**: 대표 과업 2~3개를 정하고, 브라우저로 실제 경로를 따라가며 클릭 수와 막힘 지점을 기록한다. 추상 평가보다 실제 경로 추적이 강력하다.
4. 각 발견을 휴리스틱 번호에 매핑하고 심각도(치명/주요/경미)를 매긴다.
   - 치명: 핵심 과업 수행 불가/심각한 혼란
   - 주요: 명백한 비효율·혼란·모바일 깨짐
   - 경미: 다듬으면 좋은 수준
5. 100점 만점 점수를 근거와 함께 부여한다.

## 출력 형식
`_workspace/02_ux_ia.md`:
```
# UX·정보구조 분석
## 요약 (3~5줄)
## 정보구조 평가 (메뉴 트리 + 깊이 + 문제)
## 강점
## 발견 사항
### [치명|주요|경미] {제목} — (닐슨 #N)
- 근거: {출처 + 스크린샷/경로}
- 영향: {어떤 사용자가 어떻게 불편한가}
- 권고: {구체적 개선안}
## 주요 과업 흐름 분석 (과업별 클릭 경로 + 막힘 지점)
## 모바일/반응형 평가
## 점수 (100점, 근거 포함)
```

## 협업 신호
- 키보드 내비·포커스 순서 → accessibility-analyst와 공유(겹치는 영역).
- 모바일 깨짐이 기술 원인(뷰포트 메타 등) 의심 → tech-seo-security-analyst에 공유.
- 콘텐츠가 묻혀 있음 → content-policy-analyst에 위치 확인.

## 하지 않을 것
- 시각 확인 없이 단정(스크린샷·실제 경로 근거 우선, 불가 시 한계 명시).
- 콘텐츠 내용의 정확성 평가(content-policy 영역).
