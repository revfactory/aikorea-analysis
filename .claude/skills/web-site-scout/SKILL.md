# Web Site Scout — 사이트 정찰·인벤토리 구축 절차

후속 분석가 4명이 공유할 **단일 데이터 토대**를 만든다. 분석가별로 따로 크롤링하면 커버리지가 어긋나고 서버에 중복 부하를 주므로, 여기서 한 번에 정확히 수집한다.

## 왜 이렇게 하는가
수집과 분석을 분리하면 (1) 모든 분석가가 동일한 근거를 보아 결론이 정합적이고, (2) 사이트에 한 번만 접근하며, (3) 사후에 발견을 원본과 대조 검증할 수 있다. 그래서 이 단계의 목표는 "판단"이 아니라 "재현 가능한 사실의 축적"이다.

## 도구 분담
- **WebFetch**: 페이지 본문 텍스트, robots.txt, sitemap.xml 등 텍스트 대량 수집. 빠르고 가볍다.
- **브라우저(mcp__claude-in-chrome__\*)**: 동적 렌더링 콘텐츠, 스크린샷, 네트워크 기록(read_network_requests), 콘솔(read_console_messages), 실제 헤더. 시각·동적·성능에 필수.

> 브라우저 도구는 사용 전 ToolSearch로 로드한다(`select:mcp__claude-in-chrome__navigate` 등). 세션 시작 시 `tabs_context_mcp`로 현재 탭을 확인하고 새 탭을 만들어 작업한다.

## 절차

### 1. 진입 및 구조 파악
1. 시작 URL을 WebFetch로 받아 메인 페이지의 내부 링크·메뉴를 추출한다.
2. robots.txt와 sitemap.xml을 확인한다(`{origin}/robots.txt`, `{origin}/sitemap.xml`). 크롤링 허용 범위와 공식 페이지 목록을 파악한다.
3. 발견한 내부 링크를 따라 1뎁스씩 확장하며 페이지 목록을 만든다. 외부 도메인 링크는 목록에만 기록하고 따라가지 않는다.

### 2. 페이지별 수집
각 페이지에 대해:
- 본문 텍스트 (WebFetch)
- 핵심 HTML 구조 발췌: `<title>`, meta 태그, 헤딩 위계(h1~h6), 이미지 alt 속성, 링크, 폼·입력 레이블, `lang` 속성
- 응답 코드, 최종 업데이트 흔적(게시일 등)

주요 페이지(메인 + 각 메뉴 대표)는 브라우저로도 방문하여:
- 데스크톱(1280px+) / 모바일(375px) 스크린샷
- 네트워크 요청 기록(리소스 크기·수·헤더)
- 콘솔 오류

### 3. 기술 메타데이터
- HTTP 응답 헤더(보안 헤더 포함), 쿠키 속성
- HTTPS/인증서 여부, 리다이렉트
- 외부 리소스(폰트, 스크립트, 분석 도구) 목록
- 깨진 링크(4xx/5xx) 목록

### 4. 산출물 작성
`_workspace/01_inventory/` 아래에 저장:
- `sitemap.md` — URL · 제목 · 메뉴 경로 · 응답 코드 표
- `pages/{slug}.md` — 페이지별 텍스트 + HTML 구조 발췌 (상단에 출처 URL·수집 시각)
- `screenshots/{slug}_{desktop|mobile}.png`
- `tech_metadata.md` — 헤더 · 쿠키 · 성능 · 외부 리소스 · 깨진 링크
- `INVENTORY.md` — 색인 + 수집 요약

`INVENTORY.md` 필수 항목:
```
# 수집 인벤토리
- 대상: {URL}
- 수집 일시: {YYYY-MM-DD HH:MM}
- 수집 도구: {WebFetch / 브라우저 사용 여부}
- 총 페이지: {N}개 (전수 / 샘플링 {기준})
- 미수집·실패: {목록과 사유}
- 파일 색인: {sitemap.md, pages/, screenshots/, tech_metadata.md}
```

## 규모 조절
- 페이지 30개 이하: 전수 수집.
- 30개 초과: 메뉴별 대표 페이지 + 메인을 우선하고, 목록형 페이지는 대표 샘플만. **반드시 `INVENTORY.md`에 샘플링 기준과 제외 범위를 명시한다.** 침묵의 누락은 "다 봤다"는 오해를 부른다.

## 예의 있는 크롤링
- robots.txt 준수, 같은 URL 재요청 금지, 정부 사이트(.go.kr)에 빠른 연속 요청 자제.
- 로그인·결제·개인정보 입력 페이지는 수집하지 않는다(공개 정보만).

## 하지 않을 것
- 좋다/나쁘다 평가(분석가의 몫). 단, 404·깨진 링크 같은 객관적 실패는 사실로 기록한다.
- 비공개/인증 영역 접근, 취약점 탐침, 부하를 유발하는 반복 요청.
